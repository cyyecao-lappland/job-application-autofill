# 网申回填

## 本机存储位置

网申程序、资料、映射和运行数据由 skill 的 `config.local.json` 定位，启动时先执行 `scripts/resolve_config.py`，见 [本机配置与迁移](installation-config.md)。新运行使用解析结果中的位置，不在 OneDrive 求职材料目录重新创建运行库、浏览器配置或依赖副本。旧的已迁移运行路径只在程序既有迁移表适用时转换；新机器不能直接沿用旧电脑的绝对迁移目标。其他 OneDrive 运行路径直接报错。

实际检查点入口使用项目 `edge_form_graph.storage.SqliteSaver`。大型序列化数据通过普通记录 ID 引用共享压缩内容，重复内容按字节比较；没有哈希或校验和。协调器退出后自动保留最近 32 个历史步骤，另保留未知保存核对状态与所需子流程／跨流程引用，回收无引用内容并按阈值缩小文件。保留步骤使用原 ID 和中间写入；保存命令关联另存紧凑索引。当前状态、writer journals 与投递证据不按任务年龄或失败状态整批清除。不能用上游默认 serializer 直接读取新格式，也不能另建全量数据库副本作日常备份。

目标是尽快交付大部分已填好且状态清楚的申请。计划通过、输入返回、页面匹配、网站保存是不同结果；只根据真实工具返回和网页观察报告进度。

## 控件契约与本机最新约定（2026-09-28）

本节优先于旧参考文件中的保密传递和“回读不全必须阻塞”规则。用户明确要求个人字段走普通程序路径：直接传值、直接回读、直接比较，不因为手机号、证件或密码类别添加脱敏层、保密引用或确认步骤。无法完整回读时记录 `verification_skipped` 并继续后续字段／模块，不重填，不记为核验成功，也不据此固化映射或操作方法。完整值不匹配仍处理为异常；调用未结束、传输未知以及保存／新增／提交未知不适用跳过规则。

控件扩展使用统一能力契约。注册表通过 `protocolVersion + registryVersion + name/adapterVersion/targetTypes/protocolVersion` 逐项比较，禁止用哈希代替；不一致报 `CONTROL_REGISTRY_MISMATCH` 并停止写入。执行器报告实际加载的驱动声明。实施与扩展步骤见 [控件能力契约](control-contract.md)。

## 授权与资料

- 用户于 2026-09-24 明确：其指定 JSON 内的资料均允许用于网申填写，不能仅因“敏感信息”分类新增确认、单独安排流程或阻塞批次。证件字段按同批普通字段调度；日志不展示完整号码不应影响自动填写。授权限于用户指定的申请用途，不等于向无关目标公开资料，也不改变正式提交的授权范围。

- 沿用当前申请已有的填写、暂存授权。用户已经要求使用现有方法填写时，不再要求回复“开始”或重复确认资料传输。本地计划、脚本、预检链接是进度信息，不是新审批关卡。新声明、缺失事实、最终提交分别按实际范围处理。
- 本人资料入口为本机配置解析结果 `profile_file`。除非用户明确指定另一份资料，直接使用此文件，不重复询问已配置路径。配置或文件实际缺失、损坏时报告具体故障，不使用旧电脑路径或公开示例替代。读取后任务内复用，文件更新或用户更正时定点重读。格式与空值语义见 [资料格式](profile-format.md)。本机配置不提交到公开模板。
- 依据顺序：本轮用户更正 → JSON 已确认字段与策略 → JSON 有来源正文 → 对真正缺失、冲突、过时的信息查用户配置的履历库索引及对应条目（可选）。不能把只确认过某项推断为“只有该项”；不要重新润色已有可直接使用的正文。
- 按 `record_id` 盘点教育、实习、项目、研究、竞赛、奖项、校园和技能，遵守 `autofill_policy/presentation_policy`。实习、项目、论文各自归类；同一成果可以关联，但不能因类别混淆重复新增。竞赛和获奖要关联同一事件。
- 采用合适长度的 `description/responsibilities/achievements/texts/quick_fill`；汇总与逐条资料冲突时以当前记录为准。保留作者身份、真实研究状态、日期精度、排名范围和指标归属。
- 空值不等于“无/否”。结合 `collection_status/field_metadata` 区分未提供、明确无、不适用、不披露和待确认。先查正文再用 `missing_values` 判断缺项；历史公司的个人答案不自动用于新公司。
- 用户于 2026-09-24 持续授权：今后网申可从固定 JSON 读取并填写证件信息，无需逐次确认。按 2026-09-28 的最新要求，证件字段使用普通值传递与比较路径。此授权不含验证码、人脸验证或正式提交。年月不补造某日，不猜学位、证书编号、薪资或声明事实。真正缺失的问题集中交接，不阻塞其他确定字段。
- 用户要求全部补齐时，完整检查相关 JSON 栏目后再判断缺项。不能因一个字段要手动，就把整条记录或整个栏目直接排除。

## 页面和准备

### 本机顺序主图（2026-09-24 用户指定，优先于下方旧路径）

控件方法必须与字段答案分开判断。未验证的 text 元素只作候选，不默认允许直接 fill，也不凭显示文字相等记为完成。原生控件走已知方法；陌生控件由 agent 读取局部 DOM 证据，绑定已有白名单适配器，缺能力时在用户授权的代码优化范围内新增适配器并测试。每个适配器同时定义识别条件、交互顺序、业务完成条件；新弹窗/菜单必须纳入核验。当前实现包含省市弹窗和显式文本探测；不声称支持所有控件或自动生成任意安全代码。

已停止的原主图可用 `application inspect-controls` 生成只读诊断命令，经同一 Edge 执行器读取弹窗标题、控件、选项及结构。`application apply-control --label ... --source ... --adapter ...` 只选择程序白名单方法，JSON 指针由程序解析，不接受任意脚本或答案字面量。成功后方法存入 `private/control-methods.json`，只保存站点、模块、字段结构、来源及方法证据，不存个人答案或临时选择器；以后同范围可省略来源复用，每次仍需现场结构检查。此入口目前是显式 agent 例外处理，尚未自动批量调度所有陌生控件。

省市适配器按选省、等待城市候选、选市、确认、弹窗关闭及主字段回读核验。已结束的确认遇到页面延迟，可用新诊断证据走 `application reconcile-control`，不能重复点确定。原回执保留，控件已确认不代表模块已保存。旧保存未点击的修复入口需 journal 证明无点击；保存可能已派发或调用未结束时不允许借控件修复继续写入。

用户已要求程序化核对未知填写：普通字段的历史 fill 回执为未知时，主图允许同一 Edge 原标签页的有界只读 observe，不以旧请求缺少结束证据禁止读取。执行器取得真实已选值后，程序对比 before/expected/actual；匹配则跳过重复输入，原值则保持未完成，第三值为冲突，不可读/展开中的搜索文字为未知。每个旧命令最多两次只读检查，旧次数保留。只有有终结回执的普通绝对值填写、所有未知项均已匹配且无冲突时，才自动允许原主图继续未完成项。用户明确授权修复后继续时，可按命令绑定的一次性 migration 依据，对原值未变的非保密普通绝对值控件重新生成有界同目标填写；不能覆盖第三值，不能据此声称旧调用已取消，不泛化成自动无限重试。旧命令和 journal 不重放或改写，页面匹配也不证明保存。保存/新增/提交不适用这一例外。该条优先于旧参考文件中“未决时禁止只读探测”的笼统限制。

本机固定五阶段流程：**读取 → 程序填写 → agent 处理异常 → 核验与保存 → 异常处理固化为程序**。读取同时加载当前页面、配置解析的本人 JSON 和正式映射库 `knowledge_file`；程序先执行已知项，agent 集中处理剩余问题，补填仍经同一执行器。保存确认且保存后回读一致才通过 `compile_saved` 激活规则，保存前仅为候选。保存未知、未决调用或审核失效时不固化；固化失败不得重放网站保存。

用户手动补填后，先回读更新事实来源，再使用项目 `scripts/import_reviewed_mappings.py` 将独立核验的字段关系经同一保存后门槛导入正式映射库，并验证 `known_plan` 实际命中；不能以仅供 agent 阅读的旁路 JSON 代替执行器接入。字段、枚举和条件固化为映射规则；缺失控件能力需在已授权范围内实现可执行适配器，经审阅及实际控件验证再复用，不能只记录文字经验或自动执行模型生成的任意脚本。

本机当前采用“程序优先、agent 处理例外”：先用固定 JSON 信息表和 `private/form-knowledge.json` 的字段映射/枚举表生成已知操作，执行就绪项后，再由 `gpt-6-luna` 一次匹配同模块陌生字段与消解歧义。不是遇到歧义就询问用户，也不逐字段调用模型；只在推理后仍缺事实、存在无法消解的冲突或涉及个人选择时集中交接。Luna 无浏览器句柄，所有实际动作仍经同一主图与 Edge 执行器。 用户于 2026-09-25 指定资料复核也统一使用 `gpt-6-luna`：字段匹配、枚举判断、独立规则核验和内容核验均显式指定该模型，不继承主会话默认模型。主 Agent 负责调度与程序排障；若实际做了字段语义判断，报告单独标为主 Agent 介入，不能计作 Luna 完成。

字段映射按网站/表单、模块语义、标签和控件类型隔离。重复经历必须绑定 JSON `record_id`，读取时重新解析记录位置，不能把数组下标当持久身份。映射只保存来源关系和转换规则，不缓存个人答案、DOM 选择器或永久的“是/否”；条件推理只在前提成立时复用。字段关系经独立核验，枚举经等价核验与实际选中回读后仍为候选；只有对应保存范围确认成功、保存后回读一致且无未决写入，才原子激活。没有对应选项、出现冲突或条件改变时退回批量语义处理，不静默覆盖映射。

每次主图发布状态时生成 `agent-report.json` 和 `agent-report.md`，记录程序/模型命中、处理依据、模块与字段、动作阶段、耗时、真实结果、已确定原因和待验证假设。不能程序化处理的控件进入有证据的问题队列，不能绕过执行器直接接管整页。用户可依据报告要求修代码；不会自行改代码或降低保护规则。新代码需合成测试和独立的现场验证，二者分开报告。

本机新网申使用配置解析的 `project_directory` 下的原生宿主及 `run.ps1 application` 入口；具体接口见该项目 README 的“顺序主图”节。按现场页面顺序建立模块清单，并单独识别实际保存范围。相同保存范围内按顺序填写、独立核验后进入下一模块，范围末尾统一保存；独立保存范围必须确认保存后才推进。模型不能重排模块；难控件、未决写入、保存未知时停在当前模块，不自行跳到后续模块。下方旧流程中“其他独立模块继续”和 direct-tool 默认仅适用于历史兼容路径，不适用于此入口。

宿主仅准备已有 Edge 连接及有现场证据的模块/保存范围清单；运行中的读取、填写、保存经主图当前命令和同一执行器派发。开始前检查该申请历史 writer journals，不能另建目录消除未知写入。自动保存范围经 verify_autosave 等待新的成功信号、核对值，再刷新同一原标签页回读；刷新前必须确认已保存且无未决写入。范围未知或隐藏模块尚未完成发现时明确报告支持边界。不得改用旧单模块入口或直接点击来规避主图。此约束不代表已撤销主 Codex 会话的工具权限。

本机主图可给已观察模块附 `snapshot`；程序优先模式不再预先启动整页模型映射。默认两个、最多三个无工具模型用于独立核验；同一保存范围内串行填写、范围末尾并行独立核验，全部通过且回读未变化才保存。现场变化只重处理受影响部分，模型工作线程不得持有浏览器句柄。

保存按“点击派发／点击返回／确认弹窗／结果观察”分别落盘。点击和后续读取均已结束、业务结果仍未确认时，由主图派发一次只读 `reconcile_save`；不自动重放保存。读取自身传输超时仍属未决，不能只因点击已返回就继续。原生弹窗仅能读到类型时不猜正文、不自动接受；页面弹窗只有现场绑定的普通保存确认才能点。用户明确已手动处理旧保存时，使用 `application reconcile --journal ... --user-saved --basis ... --run-dir ...`，同一 Edge 页核对值后单独记录 `superseded_by_user`；不改旧 journal，不据此声称旧自动保存成功或远程调用已终止。普通“继续”不构成这种手动处理证据。

采用“发现 → 映射 → 当前批次验证 → 有界执行 → 增量发现 → 模块核验与保存”。先读 [独立核验流程](independent-checks.md)。已确定来源、记录归属、旧值、定位、方法和依赖的字段，可在批次验证通过后立即填写，不等待整页计划全部就绪或整个申请的独立规则核验。未就绪操作保留自动意图并进入 deferred，只阻塞自身及依赖项；deferred 不等于 manual，也不计为完成。独立核验默认审阅原始资料和结构/值快照，疑点定点查页；共享浏览器串行交接。

操作前先读 [连接检查器](connection-contract.md)，用当前工具的发现接口查找用户已有申请页，确认浏览器、实际工具和标签页身份，再做只读探测。页面已打开不等于工具已连接；不同浏览器工具不共享会话。不自动启动另一浏览器或新建会话。复用用户指定浏览器和申请页。先核对目标页面、字段标签、控件类型、现值、必填项和记录边界。已展开的空白表单可以直接填写，不再次新增；尚未展开不等于没有栏目。编辑中不能为了盘点切走并丢失草稿。

已有可用句柄直接复用；确需取得或恢复句柄时使用连接检查器登记尝试，不把普通字段定位失败当成连接失败。保持两次连接预算，优先采用当前工具文档中适用的路径；不抢占其他任务，不用新页面替代当前草稿。

按 [岗位筛选](jd-selection.md) 记录每条经历的去向。JD 不可得就明确标注，按用户已有的网申/通用履历范围继续确定内容，不能因此反复索要相同范围的授权。

准备 `alignment-plan.json` 与 `before.json` 即可开始本地检查；完整盘点按申请保留，各小批次只更新变化部分。交接清单是执行结果，不要求开工前先写一份。是否需要 `batch.js` 由实际执行方式决定。
