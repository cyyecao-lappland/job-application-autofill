# 历史 direct-tool 兼容路径

仅用于恢复已有旧执行状态；新申请使用 SKILL.md 的原生主图。旧路径中的先读/默认工具、独立 agent 与模块推进描述不适用于新主图。

## 选择真实执行方式

先读 [执行与恢复](execution-contract.md)。默认路径的可运行接口、调度与埋点见 [direct-tool 批执行](direct-batch.md)。

1. **direct-tool（默认）**：通过当前已经可用的浏览器工具执行实际代码/动作，保存实际调用及返回证据。不要求本地脚本加载，也不要为了满足格式创建只有注释或目标清单的 `batch.js`。
2. **adapter**：仅当当前主机确实支持加载本地代码、实际浏览器适配器和可靠状态落盘时，使用 `scripts/bounded_batch.js`。没有实际实现就退回 direct-tool，不声称“脚本已执行”。不得安装连接服务或绕过工具权限来满足此模式。

优先使用浏览器 DOM/语义控件。**CUA 默认关闭，不主动请求用户开启，也不因连接或字段操作失败自动启用；由用户明确决定启用或拒绝。** 没有明确启用就报告阻塞并保留页面。填写授权不等于 CUA 授权；明确启用或拒绝都要在 interactionPolicy 中引用用户依据。执行通道按实际工具能力声明，不能将 CUA 的无障碍点击标成 browser 来绕过检查。启用后只做短而明确的操作，页面变化必须重新观察，不复用旧元素索引或坐标；一次批次使用同一工具和通道。普通文本整段输入，多个独立字段在短批次内顺序执行；不逐字符或逐字段反复推理。

`preflight.py --run <目录>` 分开输出：
- `planReady`：本地结构、来源声明、覆盖关系和旧值映射通过。
- `batchReady`（兼容别名 `ready`）：当前派发的操作具备执行方法、近期定位证据和真实完成的依赖，可以开始本批；不证明已执行或已保存。
- `deferredIds`：本次未派发的自动目标，仍在完整覆盖分母中；不能改成 manual 来让预检通过。
- `automaticCount/dispatchIds`：整份计划的自动目标和这次实际批次。零自动目标只能称为交接计划。

定位探测只检查本批次的页面、唯一字段、真实现值和控件类型；失败时修定位或跳过，不重做整份履历计划。探测过期只更新只读证据，不重新询问已获授权。工具调用编号和结果必须取自实际返回，不可自造“成功证明”。

## 执行、恢复与保存

- 同一申请保留原始开始时间、授权依据、已完成项和未决操作。30 分钟总预算包含准备、连接、填写、回读、保存；小批次、恢复和重新读取不清零。普通操作上限 120 秒，保存上限 180 秒，串行动作共享剩余时间。工具外层须留返回余量，不能把配置数字当作底层已生效。
- 当前批次验证通过后，在已确认范围内批量填写。只在首次使用未验证的输入方法时做最小操作探测与回读；不逐字段重复内容核验。必要的动态控件观察与未知写入恢复不省略。新规则只复核受影响部分；难控件不长时间排错，不阻塞独立项。Fast/Slow 按当前工具能力、方法证据、定位稳定性和结构影响决定，不按字段名称或站点模板决定。先处理 ready Fast；没有 Fast 时优先执行可解锁更多字段的必要 Slow。新增记录等结构动作单独执行，重新发现后再派发子字段。
- 只读错误：明确调用已结束且未写入时，可以修正一次或跳过，继续独立项。未决远程调用先暂停等待/核对；不能凭“读取”假定调用已经结束。
- 写入错误：区分确定未生效、部分新增、写入未知和回读不匹配。未知写入先持久记录，再只读核对；无法判定时交接，不能原样重放。
- 切换工具或 browser/CUA 通道前，先确认旧远程调用结束，保留原执行状态，重新确认同一目标并更新只读探测；不能用旧工具的探测批准新工具的操作。未决调用只能由原工具核对结束，新工具不得代为确认。
- 恢复时先看真实网页。已匹配项跳过；用户修改保留并标冲突；依赖的记录已存在且核对一致时直接使用。部分新增只能通过此前记录的稳定记录标识找回同一条空白记录并补名称，不再点“添加”。找不到可靠标识就交接。
- 每个模块按站点实际按钮保存：独立内容核验通过并修正 → 核对现场必填条件 → 在已有授权内保存 → 只读验证成功。缺必填项只阻塞该模块保存，其他独立模块继续；不能为了满足“一次保存”把各栏目留成草稿。
- 保存未知时保留页面，只读核对，不重复点击或刷新。已确认保存的模块不重复保存；保存校验明确失败后，仅在缺项已经变化并核对通过时再尝试。
- 正式提交仍单独受用户授权约束；执行器不提供自动提交动作。不要把“预览并提交”当暂存。
- 旧版本执行状态不能直接冒充新状态重跑。保留旧记录，先核对当前页面和新增记录，再迁移已完成项；尚未解决的未知动作继续保留，不能靠新目录消除。

## 核验与交接

下拉原始答案与现场选项不严格匹配时，记录字段、JSON 来源及实际可选标签，安全收起已确认归属的菜单并暂缓该项，继续同批其他独立字段。模块核验阶段集中提出字段限定的等价枚举映射，程序校验来源、候选成员资格和唯一性后再补填；不能用近似匹配改造事实或擅选城市偏好。补填后再次核验，缺必填时不保存、不越过当前顺序模块。未确认归属或未结束调用仍按原恢复约束处理。

独立内容核验须从原始资料盘点应处理记录，再检查真实页面，不能只验证填写者选中的字段。没有独立核验结果不能报告验收通过；没有保存证据不能称已保存。`preflight.py`、`verify_form.py` 均不检查核验 agent 身份，也不替代规则或内容核验；当前未接入宿主强制拦截。

`verify_form.py` 只比较提供的快照。请求 `--evidence reloaded` 必须附真实保存、重开及读取记录，缺失则降为 `page`；提供记录也不等于离线工具能独立证明网站事实。格式见 [核验格式](plan-schema.md)。

报告实际填写项、保存成功模块、未保存草稿和阻塞原因，并交代完整申请还有哪些确定内容未处理。禁止用缩小后的“3/3”代替整份完成度。手动项列“栏目/记录 → 字段 → 值或缺失事实 → 未尝试/缺资料/失败/保存丢失”，主动省略单列理由。保留当前申请页供用户接手。

`zhiye.com` 现场确认为 Phoenix 时可参考 [站点经验](zhiye.md)，不能把旧租户方法当当前站点已经验证。所有检查只约束经过它们的路径，无法阻止模型绕过脚本直接调用工具；不要承诺工具层强制隔离。
