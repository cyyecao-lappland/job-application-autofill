# Phoenix 表单兼容经验

以下为历史操作中提炼的方法，已去除个人申请记录。现场须重新核对标签、组件与保存行为，不代表当前租户已经验证。

## 定位与记录边界

- 字段 `.form-item`，标签 `.form-item__text`，完整记录 `.closest('.form')`。`.form-part` 可能只有半条记录；重复经历的 `.form` id 可能相同。
- 按已知学校、单位、项目名称定位记录，不能依赖重开前的顺序。快照中的 `recordIndex` 不跨快照复用。
- 单选在字段内按 `.phoenix-radio__radio-text` 准确文字点击，用 `.phoenix-radio--checked` 回读。
- 下拉 `.phoenix-select`，选项 `.phoenix-selectList__singleLabel`，选中标签 `.phoenix-select__tipEle`。搜索输入值不一定是选中值。
- 添加按钮从现场 `[id$="_addButton"]` 取真实标签与 id；新增后应只多一条目标记录，异常时停止该记录操作。

## 输入与保存

原生 value setter 加合成 input/change 事件可能只改显示而不进入保存数据。优先使用宿主支持的语义填写或原生编辑操作；回读匹配后仍需保存证据。

历史兼容方法 `document.execCommand('insertText', ...)` 已弃用。只有当前工具允许修改页面且本站已验证时才考虑使用；不能用只读 evaluate 写入，也不能访问框架内部对象绕过界面。

下拉菜单可能有动画和残留弹层；有界等待当前活动菜单可见、可命中，再按现场选项准确选择，不能取全页第一个同名选项。

## 交接与证据

- 地区显示已选仍可能保存丢失，应按最终完整记录核对。
- 日期需保留资料精度，不补造某日；不能凭一个日期控件的结果断言所有日期控件成功或失败。
- 未验证的级联、多选、上传等控件交接，不长时间试错。
- 成功提示、页面匹配和重开后保留是不同证据。按本站真实按钮范围分模块保存；没有其他未保存草稿时才考虑重开验证。
