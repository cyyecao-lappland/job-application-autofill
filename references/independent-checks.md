# 真实页面的两次独立核验

使用宿主现有浏览器和子 agent 能力，不要求安装专用浏览器适配器。规则核验与内容核验使用不同的独立上下文；主 agent 负责填写、修正与已有授权内的保存。不要创建新的用户任务来代替子 agent。

## 填写前：规则核验

主 agent 先勘察栏目、重复记录入口、必填条件、动态依赖、控件操作方式、保存范围和离开页面的影响，留下简短规则清单。不要把“暂未找到”写成“不存在”。

启动规则核验 agent 时只提供目标浏览器/页面标识、申请范围、用户授权与以下任务，不传入主 agent 的结论或完整对话。支持无历史派生时使用它。让核验者先独立观察，再发送主 agent 清单作差异比较：

> 核验当前真实申请页的操作规则。逐项查看栏目和新增入口、展开后字段、实际下拉选项、自定义入口、必填与级联条件，以及保存/暂存/自动保存/提交的范围与证据。标出可批量填写与需顺序交互的控件。重点区分已确认和尚未确认；尚未看到入口不能证明不存在。先返回自己的观察，之后再对照另一份清单。不要填履历、点击保存/提交、切走或刷新未保存草稿。只进行不丢失草稿的查看与展开；需要创建记录或实际填写才能验证的条件，标为待验证并交回主 agent。

每个关键结论附：栏目或控件、实际观察、工具返回或页面证据引用、已确认/尚未确认、受影响的填写或保存动作。不要仅答“同意”。不要求固定 JSON 格式。

同一页面操作串行交接：主 agent 在核验者观察时不操作页面。核验者没有浏览器访问能力时如实报告；主 agent 可提供最新完整原始页面证据供独立上下文审阅，但这只能称为快照审阅，隐藏入口等结论仍未确认，不能冒充独立实页勘察。

规则核验返回后才开始它已确认范围内的批量填写。争议或缺证据只阻塞受影响动作，其他范围继续。没有独立 agent 时可继续资料准备与勘察，但不得自签通过后开始批量填写；明确报告缺少的能力。用户明确要求变更流程时遵循新要求，并说明未做独立核验。

出现新步骤、条件字段、不同保存边界或与规则冲突的页面行为时，只暂停受影响部分，交规则核验者复核变化，不重跑整份申请。

## 批次后：内容核验

在实际保存单元内批量填写，不逐字段做内容核验；必要的控件等待、展开检查和未知写入恢复照常进行。批次结束后，启动另一名内容核验 agent，提供原始资料入口、完整申请范围、当前用户更正与授权、目标页面标识。不要提供“已填正确”或填写者选定字段作为唯一验收范围。

> 独立读取原始履历和当前真实页面，核对栏目归属、字段值、遗漏、重复、日期精度、作者身份和研究状态。先按原始资料盘点应处理的记录，再逐项检查网页；不能只检查填写者说已完成的字段。对每个问题列出栏目/记录、来源、实际页面内容、差异和建议。区分错误、缺事实、网站不支持、未处理。不要修改页面或保存，也不要把页面匹配称为网站已保存。

同样串行使用浏览器；无法直接读页时明确采用快照审阅及其覆盖限制。主 agent 按问题清单集中修正，再由内容核验者检查修改项及受影响依赖。若发现规则错误，交回规则核验者确认，不能为了填满而改写真实类别或赛事。

## 保存与结束

按真实保存范围安排内容核验与保存；独立保存模块可分批核验后保存，不必等整份申请结束。复用已有授权，不再询问相同范围的填写/暂存许可。保存条件需实际输入后才出现时，先检查现场条件；条件改变则复核受影响规则。

主 agent 不能代写两位核验者的通过结论。结束时引用真实核验结果，列出未解决项、页面草稿、网站确认保存和已重开验证的内容；没有保存证据不能称已保存，没有核验结果不能称验收通过。没有保存入口时不提出“现在保存”的不可执行下一步。

这是工作流要求。当前宿主路径没有实现工具或结束钩子拦截；现有预检脚本不检查 agent 身份、也不证明页面规则正确。不要声称这些要求已成为程序硬约束。
