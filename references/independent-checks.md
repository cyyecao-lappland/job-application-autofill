# 独立核验：快照优先，疑点查页

规则核验与内容核验使用不同的独立子 agent；不创建新的用户任务。主 agent 不能代写核验通过结论。共享浏览器串行交接；核验者读取快照时主 agent 可以继续独立批次，但核验结果必须绑定其实际审阅的模块版本，不能用于后续已经变化的内容。

## 执行与核验的阻塞范围

当前批次完成来源、记录归属、旧值、定位、方法和依赖检查后即可填写，不等待整个申请的独立规则核验。规则核验负责发现遗漏和错误；已发现的疑点只暂停受影响动作。缺少独立 agent 不阻塞已验证批次的填写，但不能宣称独立核验通过，也不能跳过保存前的独立内容核验。

## 规则核验输入

提供原始 profile 入口、完整申请范围、当前用户更正、原始结构快照及页面身份。让核验者先独立盘点，再对照执行计划，避免只审填写者选中的字段。

结构快照保留 sections、records、field semantic keys、labels、control kinds、required、visible、expanded/collapsed、loaded/unknown、add-entry availability、保存边界、捕获时间和真实工具证据。记录 sectionCoverage、hiddenContentPossible、dynamicRuleUnknown；这些状态缺失按 unknown 处理。未展开、未加载、iframe/shadow root 未遍历不能称为完整覆盖。快照不得含证件值。

默认先审快照。栏目覆盖未知、隐藏入口可能存在、动态规则不确定、保存边界不明确、记录身份不唯一或快照相互冲突时，串行交接浏览器，只检查疑点区域。不可切走或刷新未保存草稿，不新增记录，不保存或提交。需要实际操作才能验证的方法交回主 agent 做有界 slow 探索。

关键结论附栏目、观察依据、证据引用、已确认/未知和受影响动作。快照审阅只能称为“独立快照核验”，不能冒充核验者独立观察页面或发现全部隐藏栏目。

## 内容核验与保存

每个真实保存模块完成后，提供完整原始资料盘点、结构快照、执行计划及值快照。值快照包含 before、planned、after、source、readStatus 和真实捕获证据。核验者独立检查应有记录、遗漏、重复、栏目归属、日期精度、作者身份及研究状态；不能只检查 written 列表。

读不到、被遮蔽或互相冲突的值标为未知，不能当空值重填。下拉读取真正 selectedValue，不能拿搜索文字替代；日期组合全部操作结束后读回完整年月和至今状态。未知控件状态、快照冲突和保存证据不明确时定点查页。

主 agent 集中修正，内容核验者复核修改项和受影响依赖。核验通过需绑定当前模块 revision 和真实 reviewEvidence；字段变更使旧核验失效。独立内容核验通过、现场必填满足、授权有效后及时保存该模块，随后只读确认成功；不要等所有 Slow 结束。保存未知保留 pending，不重试或刷新。

结束时分别报告页面填写、独立快照核验、网站保存及重开验证。完整覆盖分母保留 deferred/manual/未发现的待核验范围。本工作流及离线脚本不验证 agent 身份，也不构成宿主工具硬拦截。
